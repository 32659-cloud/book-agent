# 需求說明

## 這是什麼
一個在我自己電腦上執行的 Discord agent。只要它開著，我 Discord Server 裡指定頻道的任何人傳一張書的封面（或書背）照片進來，網路書店頁面或電子書封面的截圖也可以，它就會辨識書名、作者、類別，記到那個人自己的書單，再回覆上傳者。agent 關掉就不處理。

## 誰會用
我自己的 Discord Server 裡、那個指定頻道的任何人，用手機或電腦都可以傳。每個人有自己的書單，彼此看不到、也不會混在一起統計。

## 使用的流程
1. 有人在頻道裡傳一張書的封面照片
2. agent 收到，先回一個「處理中」的提示
3. agent 判斷：是不是書、書名、作者、類別
4. agent 把結果記到上傳者自己的書單（預設「未讀」、「已購買」）、把照片存起來
5. agent 回覆上傳者這本書的資料，並附上「目前書單共幾本、未讀幾本、未購買幾本」

傳照片時，如果同一則訊息的文字有「想買」，這本書就記成「未購買」（當作想買清單）。這個判斷由程式比對文字，不交給模型。

## 要記錄的內容（存成一個可以一直往下加的 Excel 檔）
- 編號（每個人自己從 1 開始）
- 日期時間
- 上傳者
- 書名
- 作者
- 類別
- 閱讀狀態（未讀 / 已讀）
- 購買狀態（已購買 / 未購買）
- 是否已刪除
- 照片存放位置

照片另外存進一個資料夾，每個人一個子資料夾，檔名用「日期時間 + 書名簡稱」。

## 指令
都只處理傳指令的那個人自己的書單。

- `!書單`：列出我最近的書（最多 10 本）
- `!書單 類別名稱` 或 `!書單 作者名稱`：依類別或作者查詢
- `!未讀`：只列出我還沒讀的書
- `!未購買`：只列出我還沒買的書（想買清單）
- `!已讀 編號`：把某本書改成已讀（再下一次可改回未讀）
- `!購買 編號`：把某本書改成已購買（再下一次可改回未購買）
- `!統計`：各類別各有幾本、已讀 / 未讀各幾本、已購買 / 未購買各幾本
- `!修正 編號 欄位 新內容`：辨識錯了就改，欄位可以是書名、作者、類別
- `!刪除 編號`：把某本書從書單移掉。只是標記為已刪除，之後不顯示、不計入統計，Excel 裡仍保留紀錄，編號不會重複使用
- `!說明`：再看一次使用說明

## 不是書的時候
一樣要回覆上傳者「你傳的不是書，是某某東西」，用 agent 判斷出來的東西說明。這種照片不建檔、不進書單，也不存照片。

判斷標準是圖裡能不能清楚看出一本書的書名。書的實體照片、網路書店頁面截圖、電子書封面截圖都算書；聊天畫面、風景、其他物品的截圖不算。截圖裡出現多本書時，只處理最明顯的一本。

## 看不清楚的時候
照片模糊、只拍到一小部分、讀不出書名時，請上傳者重拍，不建檔。

## 重複的書
同一個人傳了書名和作者都一樣的書，先回覆「這本已經在你的書單了（編號 N）」，不新增第二筆。

## 畫面上 / 回覆上要有
- 收到時先有「處理中」的提示
- 處理完回覆：書名、作者、類別、閱讀狀態、書單總數與未讀數
- 指令的回覆都是文字，列出編號方便接著用 `!已讀`、`!修正`
- 所有回覆（登錄結果和指令）都公開在頻道，並用回覆功能指向原訊息
- agent 啟動時自動在頻道發一則使用說明並置頂，之後任何人都可以用 `!說明` 再看一次

## 不需要的
- 註冊、登入
- 長時間、大規模的雲端服務（這就是一支開著才會動的本機程式）
- 查書的價格、評論或內容簡介（不連外部書店或書評網站）
- 跨使用者的比較或排行
- 定時主動發訊息（例如每週提醒）；agent 只在有人傳訊息時才回應
- 用白話文修正資料；修正只用 `!修正` 指令

## 技術上我知道的
- 用 Python 3.12 + uv
- 照片用 `claude -p` 在我這台電腦上處理
- Discord 用 Gateway（bot）模式，不需要 ngrok
- 紀錄存成一個可以持續往下加的 Excel 檔
- 設定放在 `.env`：`DISCORD_TOKEN`、`CHANNEL_ID`、`CLAUDE_MODEL`、`DATA_DIR`，不能公開、不能 commit
